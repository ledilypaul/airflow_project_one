# P5-1 — Séparer le moteur des exemples

- **Date :** 2026-11-23
- **Branche :** `feat/p5-1-examples` (depuis `develop`)
- **Backlog :** `docs/audit/2026-11-23-backlog-phase5.md`, fiche P5-1

## Pourquoi

Le moteur citait IMDB et orders (configs, docstrings, tests). Un utilisateur doit pouvoir y déposer
ses propres YAML sans rien retirer.

## Ce qui a changé (vérifié par la suite, 1117 tests unitaires puis les tests d'intégration)

- `config/sources/` est vide (`.gitkeep`) ; `imdb.yaml` et `orders.yaml` sont dans
  `examples/config/sources/`, avec deux échantillons synthétiques dans `examples/data/`.
- `PIPELINE_CONFIG_ROOT` (chemin absolu, lu une fois à l'import de `pipeline.config.registry`)
  remplace la racine `config/`. Une racine sans dossier `defaults/` retombe sur
  `config/defaults/` du moteur (`ENGINE_DEFAULTS_DIR`) : `SourceRegistry.from_directory` d'une racine
  de test qui a son `defaults/` ne change pas.
- `make demo` copie `examples/data/` dans `data/` (sans écraser), exporte la variable, lance
  `make airflow`.
- `extractor_config.yaml` : `include_files: ["*"]`. Le filtrage par nom est porté par
  `source.patterns` ; un fichier sans source dédiée prend le défaut de son extension.
- Supprimés : `IMDBExtractor`, `IMDBTransform`, `config_file.json`, `dags/test_dag.py`, `sandbox/`,
  notebook, deux scripts shell, `ExcelReader.read_polars`, `JSONReader`, `HiveWriter`.
- Test garde-fou : `tests/unit/test_p5_1_engine_has_no_source.py`.
- Image de dev : `examples/config` copié et `PIPELINE_CONFIG_ROOT` fixé, pour que le run kind lise
  toujours `orders`.
